# L48 override — PR #157, the fix cycle for a review that ran too late

This file is the L48 sighting log by construction. **Sighting #16.** It is
the first in this chain that clears a PR fixing defects a review actually
found — which makes it the least weak use of the instrument in the run, and
also the one that documents why the instrument was needed three merges ago.

## What happened, in order

1. #144 merged the public engine unwired (sighting #14, override, no review).
2. #153 merged the t4 rung, a `DOCTRINE.md` + paid-ladder change (sighting
   #15, override, no review) — the case §10 names explicitly.
3. A post-merge adversarial cross-read was commissioned **at that merge**:
   five independent lenses over the merged diff, every finding handed to a
   verifier instructed to refute it, plus a completeness critic. 30 findings
   filed, 11 survived.
4. It found a **HIGH severity defect live on the deployed site**: the t4 CTA
   that four separate documents describe as "hidden" was rendering in the
   production paywall, because an author `display: block` rule beats the
   UA `[hidden]` rule. This PR fixes it and five more.

**The order is the finding.** Had the read run before #153 rather than after,
the defect would have been caught in a branch instead of in production, and
four documents would not have shipped a false statement. The override
instrument did not fail here; it was used as designed, and the design has a
cost that this sequence priced exactly.

## Who reviewed

**The change under review got a real second reader — this fix cycle did
not.** The findings come from an independent multi-agent read; the fixes,
their tests, this artifact and the journal entry are again one author. The
asymmetry is the point of writing it down: what was verified was #153, not
#157.

## What this override does not cover

- **The fix for F1 is verified structurally, not visually.** No browser has
  rendered the corrected paywall. The new guard reads the markup and CSS text
  and asserts the invariant; it cannot prove the button is gone from a
  screen. **§8 gate 9 live-fire remains the outstanding gate, and F1 is
  exactly the defect class it exists to catch** — it caught this identical
  bug once before, which is why the `.polar-message[hidden]` rule exists.
  Nothing in this PR should be read as closing gate 9.

- **The live deploy was never observed.** `curl` to the product domain is
  blocked by this environment's egress policy (403 at the proxy, whose README
  forbids retrying policy denials). Every statement here about production is
  inferred from the source and the cascade rules, not measured. In
  particular: this file does not claim the fix is live, only that it is
  merged-ready.

- **The exposure window is not quantified.** `PUBLIC_TIER_SPEC.md` was
  served on the product domain from #144's merge until this fix, and the
  paywall showed a dead $9 button from #153's merge. How many people saw
  either is unknown and unknowable from here — the project runs no analytics
  by §2, which is correct and also means there is no incident telemetry.

- **Two existing test pins were rewritten by the author of the change they
  guard** (`tests/facet_rotation.test.js`, `tests/readings.test.js`), the same
  pattern sighting #15 flagged. Both were tightened rather than loosened —
  they now pin entitlement instead of a tier literal, which is what F4 was —
  but the reviewer of that decision is again its author.

- **The completeness critic raised items this PR does not close**, and they
  are named rather than absorbed: the 320px viewport question, the
  accessibility of the sealed block beyond the `aria-label` added here, and
  whether the density strip's census framing is right in principle rather
  than merely consistent now.

- **Scope:** this override covers **#157 only**.

## Recommendation

Merge order matters more than usual: **F1 is live**, so this fix is worth
landing promptly, and the live-fire pass is worth running immediately after
against the deployed page — open the paywall, confirm one CTA. If the $9
button is still visible after deploy, the fix is wrong in a way no test here
can see, and that is the single check most worth a human minute.
