# L48 override — PR #243 (dyad launch step 2: the public signing key)

**Decision:** this PR ships WITHOUT a fresh two-lane cross-model audit,
under the explicit override shape the L48 gate accepts. This file is the
sighting log.

**Why an override is honest here.** The PR is a mechanical configuration
step of an amendment that WAS audited two-lane less than three hours ago
(PR #242, `audits/claude_lanes_pr242_premerge_audit_2026-09-05_response.md`,
both lanes MERGE WITH FIXES, every finding landed). It changes no
behaviour and no doctrine:

- one constant gains one value — `DYAD_PUBLIC_KEYS` carries key 1, a
  public ECDSA P-256 JWK (`x`/`y` only; the verifier imports nothing else,
  pinned in #242);
- `DYAD_PRODUCT_URL` stays empty, so the offer is still not presented and
  the dyad is still closed for every device — a key with no url is inert;
- the one test change is a pin refinement in the direction #242's Lane A
  HIGH-2 already argued for (state pins that follow the build's state):
  a configured url requires a configured key; the reverse is allowed.

**What was verified instead, on this head.** `npm test` 62 files / 2192
tests green with key 1 configured; `sign` with the private half followed
by `verify` against the shipped configuration returns `ok:true` for the
signed token, and the suite's CLI test confirms a foreign-key token is
refused as `unverified` (exit 2). The private key was generated in a
scratch directory outside the repository root and never written under
it; `git ls-files` carries no `d` component (the PII/secret posture of
§5 is unchanged: a public key is public).

**What this override does NOT cover, named.** Whether key 1 — generated
in a cloud session and handed to the operator as a file — is the key the
operator wants to sell under is the operator's call, and it is free to
change before the first sale (no token exists under key 1; the
never-remove-a-key rule begins with the first sale). The launch doc says
so. Step 1 (the Gumroad product) and step 3 (per-sale delivery) remain
open; nothing here claims the store is live.

**Merge word:** with the controller per §10/L48, as always.
