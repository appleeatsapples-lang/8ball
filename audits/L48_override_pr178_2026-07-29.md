## What this override does not cover

- **The migration is the load-bearing part, and it was authored and tested by
  the same lane in one pass.** `RETIRED_TIERS` plus the `getRenderTier`
  persistence is what stops a genuine t3 buyer being dropped to free. It is
  covered by tests, including the stranded state pinned as a literal — but
  the scenario was *identified* by this lane, and a scenario nobody thought of
  is not covered by tests nobody wrote. **The specific residual risk: any
  other place a stored tier is read WITHOUT going through
  `resolveRenderTier` / `normalizeTier`.** This lane grepped and believes
  there is none; that belief has not been independently checked.

- **No device state was inspected.** The claim "devices can hold a stored
  't4'" is inferred from the code path being live, not observed. Nobody has
  looked at a real browser's localStorage, and the operator's own device was
  told to visit that URL — so the first real test of this migration will be
  the controller reloading the page.

- **Three doctrine clauses in one day on one subject** (v0.58 add, v0.59
  correct, v0.60 retire). Each is individually argued; none has been read by
  anyone else; and a constitution amended three times in a day by its
  implementer is a governance smell regardless of whether each amendment is
  right.

- **The retirement does not answer the question that prompted it.** Whether
  the read is worth selling at all is unresolved; it is now bundled rather
  than justified. If the answer is eventually "no", the honest next step is
  removing it from the sheet, not moving it again.

- **The §5.D share pass is still not done**, and it is the one piece of work
  that would make an exposure tier mean anything. This PR names it as the
  prerequisite; naming is not doing.

- **The local PII audit did not run.** In-suite CI scan passes.

- **Scope:** this override covers **#178 only**.

## What is genuinely reassuring

The change removes a price rather than adding one, so its failure modes are
smaller than the change it reverses. The migration is pinned by a test that
constructs the dangerous state directly rather than through the happy path.
`content/` and `core/public.js` are byte-untouched, so the engine that three
clauses have argued about is exactly the engine that shipped in #144. And the
Price column in §1.D stops contradicting itself, which no amount of review
would have achieved while the rung existed.

## Recommendation

If a cross-model read is ever commissioned, the unit is now **§1.D v0.58 +
v0.59 + v0.60 read together** — add, correct, retire — plus the migration in
`core/payments.js`. The interesting question for a reviewer is not whether
each step was right but whether the sequence should have happened at all in
one day inside one lane.
