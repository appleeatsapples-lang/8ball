## What this override does not cover

The change is unreviewed by any second model. Its blast radius is CI and
the test suite, not the runtime — no product code ships here. That is a
real mitigant and the reason the residual risk is lower than #122's. But
the risk is not zero, and it concentrates in the pins' **oracles**, which
are the part a second model would actually have checked:

- **The divergence allow-lists are self-blessed.** 16 entries in
  `tests/cities_search.test.js` and 39 in `tests/countries.test.js` record
  where the shipped tables deliberately differ from ICU. They were derived
  programmatically from the current tables by the same lane that then
  declared them intentional. If any one of them is a latent typo rather
  than a house rendering, this PR pins the typo as correct. A staleness
  check forces an entry out of the list once it stops diverging; nothing
  checks that it *should* diverge.

- **The four lunar-new-year divergences are now pinned to the current
  implementation.** 1916, 1954, 2027 and 2030 disagree with ICU by one day,
  and no §3 Hong Kong Observatory checkpoint covers them. The test records
  both values and locks ours. If `core/calendar.js` is the wrong side of
  any of those four, this PR cements it and makes the future correction
  look like a regression. Named in the test, the journal entry and the
  survivor record; unresolved by any authority, and this override does not
  resolve it.

- **The centroid pins were rewritten mid-flight, not replayed.** The
  2026-07-25 strip moved `defaultLat`/`defaultLng` out of `COUNTRIES`, so
  the sign checks were re-pointed at `tests/country_centroids.fixture.json`.
  Their subject changed from the module to the fixture. The fixture still
  feeds product code through the legacy rising replay, so the check retains
  meaning — but that re-pointing is a judgement no second model reviewed.

- **The ICU oracle couples the suite to the runner's ICU version.** Region
  names are not stable across ICU releases (precedent: `TR` rendered
  "Turkey" before ICU 71 and "Türkiye" after). A runner upgrade that
  changes any of the 224 + 240 renderings turns the suite red on a PR that
  touched nothing. Evidence the oracle currently agrees across two
  independent environments: these tests pass both in the authoring
  container and on `ubuntu-latest` / node 20 in the `test` job. That is a
  maintenance liability this PR introduces knowingly, not a defect.

- **`tests/l48_gate.test.js` pins the predicate as this lane read it.**
  It asserts every historical verdict artifact on disk still passes, which
  bounds over-tightening. It cannot tell whether the accept/reject set is
  the one the doctrine *intends* — only that it matches what ships today.

- **Scope note:** this override covers **#132 only**. PR #133 (the
  added-only guard, stacked on this branch) is a separate PR number and
  needs its own artifact once retargeted to `main`. It also currently draws
  no CI at all, so nothing has yet executed its workflow change outside the
  authoring container.
