- **What this override does not cover — the loop is closed single-vendor.**
  This is materially weaker than the ordinary override, and the difference
  should not be lost. In a normal case one lane writes a change and no second
  model reads it. Here the *entire chain* is one vendor: Claude found the
  defect, Claude judged its severity, Claude wrote the fix, and Claude wrote
  the mutation tests that certify the fix works. A wrong fix that also passes
  its own author's mutation tests is precisely the failure this arrangement
  cannot detect. The specific unexamined risk: `--no-renames` changes what
  **every** consumer of `CHANGED=` sees, including the journal-touch and
  audit-artifact gates in the `test` job, and no independent party has checked
  that a legitimate rename-bearing PR is not now wrongly blocked.

- **Counter-consideration, recorded because it cuts the other way.** The P0 is
  live on `main` right now: any PR can rename a non-`.md` file to a `.md` path
  and delete this gate's own regression pins, the PII scanner, or the
  dependency-discipline check with both checks green and no artifact. Holding
  this fix for a relay leaves that open. The override therefore trades an
  unaudited fix against a known-exploitable gate — not against a safe status
  quo. That is a real trade with a defensible answer either way, and naming it
  is the point of this file.

- **Ledger note.** With this file, 11 of the 17 recorded sightings clear by
  override, and 8 of the artifacts filed on this date are overrides rather
  than verdict responses. The ledger lens of the #159 audit raised exactly
  this: the override is becoming the default path rather than the exception.
  Filed as an observation for the controller, not a judgement.

- **Numbering correction, recorded rather than silently fixed.** This file
  first claimed **#16**. That number was correct against the ledger when it was
