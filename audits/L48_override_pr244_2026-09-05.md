**Why an override is honest here.** One constant changes:
`DYAD_PRODUCT_URL` goes from empty to the controller's bare Buy Link.
The BEHAVIOUR this enables — the offer anchor with its href, the about
modal's open paragraph, the entry/offer swap, the href strip on hide —

live-fired it with a test url and a throwaway key, and the suite was made
honest about it (state pins follow the build). No behaviour is new; a
value is.

**What this PR DOES change on deploy, named rather than minimised.** It
turns the store on. Every unentitled visitor sees a price and a link to a
third-party checkout. That is the controller's decision, given in the
controller's words, and it is the product model doctrine v0.81 states.

**What was verified instead, on this head.** `npm test` 62 files / 2192
tests green in the configured state; an in-container Chromium live-fire
against THIS tree with the real key and the real url: offer with the
Buy Link href, target `_self`, described by its note; the open about
paragraph; `?paid=t5` stripped and inert; a foreign-key token refused; a

url exists, is published, and charges USD $3 once — the session's egress
policy blocks the storefront, so that is the controller's statement and
one browser check before announcing. Whether step 3 (a signed link per
sale, sent by hand) is an operation the operator can sustain — the
launch doc says it is manual until a separate doctrine decision.
